# 03 文本查看器-测试说明

套件：`ui-cw-textviewer/tests/host.spec.ts`，**18 个用例**（4 describe）。直调
`createTextviewerHandler`；真实临时文件夹具（字节级构造编码场景）。

## 用例逐项

### clampReadLimit（1 个）

- 默认 256KB、钳制到 [1, 1MB]、非法输入回落默认

### encoding detection（3 个）

- BOM 判定：UTF-8 / UTF-16LE / UTF-16BE / 无 BOM
- **严格 UTF-8 失败才回退 GBK**（`中文` 的 GBK 字节夹具）
- UTF-16 走 WHATWG 解码器（BOM 自动剥离）

### isWithin（1 个）

- 平台分隔符精确比较（`D:\work` 不匹配 `D:\workspace`）

### textviewer handler（13 个）

- 未知端点 bad-request
- renderer 端点：正常提供（注入假 bundle）/ 缺失时报错
- 读文件：UTF-8 整读（含中文、行数语义）/ UTF-16LE（BOM 剥离）/
  UTF-16BE / GBK 回退（`中文\r\n` 行数 = 1）
- 首块 NUL 嗅探识别二进制
- 600KB 大文件分块 + 拼接还原（字节偏移语义）
- limit 钳制 + **UTF-16 奇数偏移对齐到偶数**（offset 5 → 4，'ello' 完整）
- 越界 offset 返回空块（truncated=false）
- 越出锁定根拒绝
- 缺失文件 / 目录目标（"not a regular file"）干净失败

## 传输层验证（L3/L4）

- **L3 探针**（改动端点后）：PowerShell 两步——`?token=` 换 cookie →
  POST `/textviewer/<端点>` 信封；验证 read-text/renderer ok、list 已移除
  返回 bad-request（配方见 04 手册）
- **L4 渲染管线**（改动 renderer.tsx 后）：Node 脚本读 `lib/renderer.js`，
  用 `new Function('module','exports','require', ...)` 包装 + require shim
  求值，断言导出三件套可调用、cpp 高亮输出含 `<span class="line">`、
  MarkdownView 渲染出 `<table>`——与浏览器 loader 完全同路径
  （浏览器里 `require` 兜底走 loader 模块表，脚本里用 createRequire 模拟）
