# dsh-plugins（dsh 插件开发经验仓库）

本仓库不是插件本体，而是 **dsh web 外部插件开发的沉淀库**：三个插件
（文件浏览器 / 终端 / 文本查看器）在工作区内统一编写，但各有独立的 git
仓库（见下表）；本仓库只跟踪**经验文档**——换会话区后，读这里的本地文件
即可恢复"插件怎么做、注意点在哪、正式版与测试版区别是什么"的完整上下文。

## 项目规范（先读）

## 工作区布局

| 路径 | 说明 | 版本控制 |
|---|---|---|
| `ui-cw-fileexplorer/` | 右侧文件工作台 dock（文件树 + Git 分支 + 历史） | 独立仓库 |
| `ui-cw-terminal/` | 底部终端面板（ConPTY） | 独立仓库 |
| `ui-cw-textviewer/` | 右侧文本查看器 dock（Shiki / Markdown / 分块流式） | 独立仓库 |
| `.dsh-test-home/` | 测试用独立 DSH_HOME（link: 直连插件目录，build 即生效） | **忽略，不入库** |
| `经验记录/` | 本仓库主体：一点一文件的构建经验 | 本仓库 |

`.gitignore` 忽略 `ui-cw-*/` 与 `.dsh-test-home/`：插件各有独立 git 历史，
测试环境是随时可删的开发设施。

## 快速上手

```sh
# 测试服（改动 build 后重启即可生效，浏览器刷新加载新 bundle）
$env:DSH_HOME='D:\_dev\dsh-plugins\.dsh-test-home'
node D:\framework\deepseek-harness-test\apps\cli\lib\bin.js --profile web-fileexplorer --port 3099 --no-open

# 正式服（用户自己起，跑 harness 源码；发布插件后需重启才加载新 bundle）
node --import tsx/esm apps/cli/src/bin.ts web --port 3081
```

详细差异见 `经验记录/05-发布流程-测试版与正式版` 与 `经验记录/13-开发环境`。
