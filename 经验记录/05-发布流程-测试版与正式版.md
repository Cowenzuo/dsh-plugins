# 05 发布流程-测试版与正式版

同一份源码，两套环境：**测试 profile**（开发迭代）与**正式 profile**（用户
日常使用）。核心区别在插件安装方式：link 直连 vs vendor tarball。

## 测试版（`.dsh-test-home`，端口 3099）

```
D:\_dev\dsh-plugins\.dsh-test-home\            # 独立 DSH_HOME（可随时删除）
└── profiles\web-fileexplorer\
    ├── package.json        # 依赖用 link: 协议直连插件源码目录
    └── node_modules\@dsh-plugins\*\           # junction 指向插件目录
```

- `"@dsh-plugins/ui-cw-textviewer": "link:D:/_dev/dsh-plugins/ui-cw-textviewer"`
- **build 即生效**：junction 直连，改完 `pnpm build` → 重启测试服 → 浏览器
  刷新就加载新 bundle，不走打包/安装
- 启动：`$env:DSH_HOME='...\.dsh-test-home'; node D:\framework\deepseek-harness-test\apps\cli\lib\bin.js --profile web-fileexplorer --port 3099 --no-open`
- 测试服 token 每次启动不同：从服务器输出拿 URL（`http://127.0.0.1:3099/?token=...`），
  浏览器必须带 token 访问（换 cookie 后才免 token）

## 正式版（`C:\Users\cowen\.dsh\profiles\web`，端口 3081）

- 依赖指向 vendor 罐头：`"@dsh-plugins/ui-cw-fileexplorer": "file:./vendor/dsh-plugins-ui-cw-fileexplorer-0.1.0-rc2.tgz"`
- 插件被 node_modules 安装的**快照**——改源码不生效，必须重新发布 + 重启 dsh
- 正式服由用户自己启动（跑 harness 源码 tsx）：`node --import tsx/esm apps/cli/src/bin.ts web --port 3081`；
  发布后**用户重启才加载新 bundle**

## publish.ps1（一键发布正式版）

流程：`pnpm build` → `pnpm test`（任一失败中止）→ `npm pack` → 清旧罐头 →
复制到 profile/vendor → 正则替换 package.json 依赖行 → 删
`node_modules/@dsh-plugins` → `pnpm install` → 提示重启。

**发布前必须手动做的**：profile 清单里先加上插件依赖行 + `dsh.profile.bundles`
数组项（脚本只替换已存在行的版本，不会新增）。新插件首次发布 = 手动加两处 +
跑脚本。

**publish.ps1 的坑（踩过）**：
- 脚本含中文，文件必须 **UTF-8 带 BOM**（Windows PowerShell 5.1 按 GBK 解析
  无 BOM 文件会乱码）
- **不要管道 `2>&1`**：EAP=Stop 下 pnpm.ps1 的 stderr 回显会被当成终止错误
- 后台 job 跑 pnpm 要 `Push-Location`（workdir 参数对后台任务不可靠）
- 发布后 `package.json` 会被 pnpm 重排格式——属正常，别 git checkout 掉
- **版本号策略（2026-09 修订，见根目录《版本管理规范》）**：
  - 本项目日常"发布" = **集成发布**：把当前代码集成进正式 profile 供日常
    使用，**不升版本号**——同名 tgz 反复覆盖重发
  - **同版本重发机制已实测**：同名 tgz 换内容 → publish.ps1 删
    node_modules/@dsh-plugins → pnpm install → pnpm 重算 file: 依赖
    integrity 并自动更新 lockfile，装到**新内容**（无需 --force；
    frozen-lockfile 复检无漂移）
  - 版本号（`0.1.0-rcN` / 正式版）只在**定版发布**时变更——定版是用户
    专门发起的独立活动，不走日常集成流程

## 流程模板（每次迭代）

1. 改代码 → `pnpm typecheck` + `pnpm test` + `pnpm build` 全绿
2. 重启 3099 → 用户浏览器验证（视觉确认是关键验收）
3. 用户确认 → 提交（规范见 12-提交规范）→ 若为正式版：清单加依赖 →
   `.\publish.ps1` → 用户重启 3081
4. 修问题走 1 重来；测试服用完即停（用户叫停或征得同意）
