# 08 终端-ConPTY重放吞并与resize所有权

底部终端面板（ConPTY）沉淀：**重放完整性**与**面板几何**两个问题的最终
设计。核心原则：重放是"纯输出回放"，任何终端自身产生的控制序列都不该
进 transcript；面板宽高由两方各管一半，避免互相覆盖。

## 重放吞并（replay swallowing）

- ConPTY 在 resize 时会回放整屏控制序列（`\x1b[2J` + 重画等）：若这些进
  transcript，历史里会出现"清屏重画"垃圾
- 服务端**吞掉 resize 触发的重放**：transcript 保持纯输出 + 光标尾巴；
  完整屏幕在重放结束时以**一次 `screen` 快照**整体下发
  （`read(reset: true)` 时重置并回放快照）
- 客户端应用快照前做**滚动回保护**：快照会擦掉 xterm 滚动历史，先记
  滚动位置/内容，快照落地后恢复——用户的历史不许丢

## resize 所有权切分（关键设计）

- **高度 = 客户端所有**：面板高度变化只改 CSS/几何，**绝不通知 pty**
  （pty rows 保持稳定，避免每次拖拽都触发重放风暴）
- **宽度 = pty 所有**：列数变化才通知 pty（`ptySizeRef` 高水位，只提交
  cols），客户端 debounce 后 fit
- 单写者轮询：转录读取与 resize 提交互斥，杜绝"reset 与并发写交错"
  产生的 `{{`、`;44h` 残片

## 历史踩坑（按根因）

| 现象 | 根因 | 修法 |
|---|---|---|
| 残留 `{{` / `;44h` 碎片 | reset + 并发写交错 | 单写者 + 吞并 |
| 收起/展开后错行 | 闭包捕获了挂载时的 workspace（replay 用了旧引用） | `workspaceRef.current` |
| 原子重绘后仍有 straggler 字节 | 重绘与外层字节交错 | 吞并设计（见上） |
| 快照擦掉滚动历史 | scrollback 被替换 | 客户端滚动回保护 |
| SU 滚动序列不进 xterm 历史 | `\x1b[nS` 在 xterm 里不回填 scrollback（headless 复现确认） | 放弃 SU，改用快照方案 |
| PSReadLine 绝对定位导致视图跳变（残余风险） | 面板比 pty 行数矮时 PSReadLine 绝对定位重绘 | 用户后续自行重做逻辑 |

## 交互约定（用户拍板的需求）

- 底部面板**不挤压侧边 dock**（宽度变量联动，见 02）
- 默认收起；标题栏整条点击切换（选区/拖拽守卫）；收起按钮在标题栏右侧
- clear = 真正清屏；会话内存态（不落盘）；无记录会话 → 自动新建
- 标签页列表在右侧；新建/清屏入口在列表内；高度拖拽 80px 下限
  （≠ 30px 收起态）；主题感知背景/ANSI/光标/选区
